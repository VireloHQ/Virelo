# Security and edge-case audit — 2026-10-27

What this repo does: Virelo serves a local video library through an authenticated
npm server. Virelo-Web runs a separate browser-only player. This review assumes
one server process, multiple trusted accounts and simultaneous viewers, including
connections through an HTTPS proxy or tunnel. It is not a multi-process hosting
or penetration-test certification.

## Must fix — addressed

1. **Public names could pass private-address checks.**
   - What this is: the Host allowlist is a defense separate from account authentication.
   - Problem: DNS names beginning with private-address or IPv6-like prefixes were accepted as addresses.
   - Fix: parse authorities once and validate actual IP families/ranges in `src/request-security.ts`; reject proxy markers for local-only capabilities.
   - If left unchanged: unexpected public Hosts could reach the application without an explicit allowlist. Authentication was still required.

2. **Filesystem aliases crossed cache and library boundaries.**
   - What this is: source reads, cached HLS/audio and generated-file cleanup must stay within their intended folders.
   - Problem: repointed roots, junctions and hard links could return another folder's bytes, change timestamps, or overwrite/remove a linked original during encode/cleanup. These cases require local filesystem changes or unsafe folder configuration, not an arbitrary remote upload API.
   - Fix: canonical library roots and alias-aware media identity, guarded generated paths, checked cache hits/cleanup and hard-link rejection. Safe generated artwork remains available offline. Re-registering ancestor aliases preserves IDs and personal state; ambiguous or unavailable legacy roots cannot transfer grants, adopt old media IDs through SQLite conflicts or prune retained identity. Recovery limits are documented in `SECURITY.md`.
   - If left unchanged: account library scope and the read-only-originals promise could fail after an alias changed.

3. **Pending work could outlive access revocation.**
   - What this is: probing and subtitle conversion finish asynchronously.
   - Problem: a request accepted before revocation could return private output afterward or start conversion with stale permissions.
   - Fix: recheck the current session, library scope and playback/conversion permissions after awaited work and before sending resources.
   - If left unchanged: disabling access would not consistently stop work that had not yet sent its response. Already downloaded/buffered data cannot be recalled.

4. **Startup pruning could treat overlapping media as disposable cache.**
   - What this is: startup removes unused generated playback files over budget.
   - Problem: an explicitly configured or retained media library inside the cache could contain an original named like a generated segment.
   - Fix: check library overlap before pruning and retain deletion guards. Resolve both sides natively, including Windows 8.3/long-name aliases. Keep the UI and original playback available, but refuse unsafe cache operations with `409`.
   - If left unchanged: a misconfigured folder layout could delete an original before the library was registered.

5. **Concurrent encodes could exceed the cache budget.**
   - What this is: several viewers can request segments at once.
   - Problem: separate size checks did not reserve space while work was queued; a fixture retained 167,772,155 bytes under a 134,217,728-byte limit.
   - Fix: reserve budgets atomically inside an admitted work slot through encoding/finalization, and release each reservation once, including failure/cancellation. Requests waiting for a work slot do not consume the disk budget.
   - If left unchanged: a burst of requests could exceed the configured disk limit.

6. **Remote metadata and artwork had no byte limit.**
   - What this is: optional providers return JSON and image bodies.
   - Problem: the timeout did not bound memory/disk use during a fast oversized response.
   - Fix: cap decoded JSON at 16 MiB and artwork at 32 MiB; cancel oversized streams and remove partial downloads, regardless of Content-Length.
   - If left unchanged: a faulty or compromised provider could consume excessive resources. Provider trust and network egress policy remain operator concerns.

7. **Malformed settings could persist as the wrong runtime types.**
   - What this is: server settings control metadata requests, scanning and queue behavior.
   - Problem: values such as the string `"false"` or unknown enum choices could be saved instead of rejected.
   - Fix: centralize defaults/validation in `src/settings.ts`, reject invalid patches atomically and ignore malformed stored values when reading.
   - If left unchanged: saved settings could behave differently from their intended meaning or break client controls.

8. **Preference races and restricted storage were inconsistent.**
   - What this is: npm account preferences and Web device preferences have different ownership.
   - Problem: stale appearance reads could replace newer saves; account language could interfere with device language; messaging/storage failures could break UI effects.
   - Fix: cancel superseded reads, refresh cross-tab changes, isolate account locale lifetime, validate locale loads and guard optional browser storage/messaging. Invalid durations format as zero.
   - If left unchanged: settings could appear to revert, leak between account/device contexts or leave sign-in unusable in restricted browsers.

## Should fix — addressed

9. **HeroUI's stylesheet imported unused components.**
   - What this is: HeroUI provides accessible Button, Input, Switch, Modal and Popover primitives beneath Virelo's custom appearance.
   - Problem: importing the full stylesheet also shipped calendar, date-picker, color-picker and OTP rules with no application consumers.
   - Fix: retain the library and shared foundations, but import only used component styles. Preserve CloseButton and the EmptyState/Skeleton class overlaps; test the import map and emitted CSS.
   - If left unchanged: users downloaded unnecessary CSS. Removing HeroUI itself would instead require replacing real accessibility and overlay behavior.

10. **Build-only dependencies and obsolete exports added maintenance cost.**
    - What this is: Inter is bundled into frontend assets, and legacy whole-film HLS helpers no longer drive playback.
    - Problem: npm still installed the font source package at runtime; two helper functions and four type-only exports had no remaining consumers.
    - Fix: move Inter to development dependencies, preserve its OFL notice, and delete the unused exports. Declare the already-used animation CSS package directly for scoped builds.
    - If left unchanged: production installs carried an unnecessary font source package, and obsolete interfaces remained misleading.

11. **Feature-branch CI ran twice.**
    - What this is: both push and pull-request events scheduled the same build matrix.
    - Problem: opening/updating a PR duplicated work, while Ubuntu media setup could use a slow package mirror.
    - Fix: run PR checks for feature changes and retain main/release-tag push checks, read-only workflow permissions and pinned media/browser runners using the official Ubuntu archive. Lock browser tooling with the rest of the development dependencies instead of re-resolving application packages after `npm ci`. Complete all OS matrix jobs even if one fails, so platform-specific regressions remain visible.
    - If left unchanged: redundant jobs and environmental stalls obscured actual regressions.

## Verification and limits

- npm: 387 tests, 385 passed, 2 platform-specific skips, 0 failures in the integrated local Windows run. The Linux/macOS/Windows CI matrix checks platform-dependent paths.
- Web: 183 tests passed with no failures/skips, including Workers configuration checks; both repositories pass the 1,242-message, five-locale completeness check.
- Browser checks cover responsive accounts and cross-tab logout with blocked messaging. Communication checks recorded 256 passes, including 96 localization checks; motion checks recorded 308 passes across both editions. The production Web build passed 270 checks over five locales at desktop/mobile widths, with no errors across 338 asset requests. Deployment checks are separate merge gates, not implied by a successful local build.
- Dependency scans returned zero published npm advisories for both lockfiles. This does not cover unknown flaws, the OS, native media tools or the deployed environment.
- The local runtime was Node.js 22.23.4. The CLI/server minimums already include the [October 2026 security releases](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases).
- Main CSS changed from 551,589 to 200,483 bytes for npm and 536,018 to 184,912 bytes for Web. Gzip sizes changed from 62,824 to 32,724 and 59,952 to 29,854 bytes respectively. HeroUI's JavaScript and accessible primitives were retained.
- Originals in generated attack fixtures retained their contents, hashes, sizes and modification times. No real media, account database or running user server was used for mutation tests.

Verdict: the reproduced issues above are addressed; public exposure still needs
strong credentials, correct HTTPS/Host/proxy settings and external access checks.
Short PINs remain supported but are not suitable Internet-facing credentials.
See `SECURITY.md` and Cloudflare's [origin parameters](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/origin-parameters/).

Lean: one production dependency moved to build time, six unused exports removed,
and 351,106 bytes of unused CSS removed from each main stylesheet. Historical local
build chunks were deliberately not deleted while an existing server may need them;
the normal clean release build does not include those leftovers.

Not checked: an actual public tunnel/provider account, Android TV/iOS or other
physical devices, screen-reader hardware, every upstream codec vulnerability,
hostile same-OS filesystem races, multi-process serving of one data directory,
or an exhaustive line-by-line review of every landing-page asset and dependency.
